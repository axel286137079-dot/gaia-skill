# 单项需求比较接口

输入顶层：base_currency、quantity（大于0）、unit、as_of、required_by、quotes。日期YYYY-MM-DD，交付日不得早于评估日；用指定评估日而非脚本机器日期保证可重现。

quotes每项：
- id：唯一匿名代号；currency：大写三位代码；unit：已换算后的基础单位，须与需求一致。
- spec_confirmed、destination_confirmed：只有明确true才通过；规格/贸易条款/目的地差异需人工确认，不能为了凑完整全填true。
- units_per_pack：每包基础单位数>0；min_packs：整数、最低购买包数>=0。
- price_per_pack_net：每包未税单价；tax_rate：用于商品和setup费用的用户税率。
- shipping_gross：含税总运费；setup_net：未税一次性费用；other_gross：其他含税费用（关税、保险等已确认成本）。
- lead_days：整数交付天数；valid_until：有效截止日；payment_terms：付款条件。
- source_ref：原始来源定位，例如“供应商A报价.pdf，第2页第4行”，避免完整私有路径或链接令牌。
- 外币报价另填 fx_to_base（1报价币种兑换多少基础币种）、fx_source、fx_date。以报价日/评估日核对，不从记忆提供汇率。

未知费用用null，不是0；有明确免运证据才填0。未知字段会列blockers，不参与排名。
invalid_input退出码2表示结构或字段非法，重新核对原件。CLI只输出JSON，不修改文件。

## 计算与限制

购买包数 = max(向上取整(需求量/每包数量), 最小包数)。
现金支出 = (购买包数×未税包价 + 未税一次费)×(1+税率) + 含税运费 + 含税其他费。
基础币种现金支出 = 现金支出×用户提供的汇率。

若商品与一次费不同税率，先把费用人工归一或分开做子表，不套一个税率。排名不考虑进项税抵扣；“省钱”只可称相对本次已确认报价的现金差额，不是已实现节省。
金额统一显示两位小数，不是各币种最小结算单位的自动适配器；涉及非两位小数币种先确认展示与付款口径。不支持整单阶梯折扣、多SKU运费分摊、按重量重新计运费、融资成本或库存残值。遇到这些条件先出澄清项或独立场景比较。

## 报告骨架

- 评估需求：规格/数量/单位/目的地/期限/币种。
- 对比表：代号、来源、包数、总数量、总现金、每需求单位成本、剩余数量、交期、付款条件。
- 排除表：报价代号、缺什么、补齐何种证明能重算。
- 决策建议：最少现金选项和风险，不能简单宣布“最佳供应商”。
- 询价补件草稿：不包含其他供应商底价，发送前由用户确认。

## 验收

A. 合成例A购10包共100件，现金2300；B起订20包共200件，现金3000；A排序在前。
B. A运费未知：A不进入排名，即使单位价低。
C. A已过期、B规格不符：排名为空，输出补件清单而非推荐。
