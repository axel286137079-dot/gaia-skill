# 字段、公式与交付规范

## 数据口径

顶层必填字段：
- currency：大写三位币种。只支持一个币种，不自动转换。
- items：1–200项，每项 label、hours、hourly_cost。成本为工时×内部小时成本。
- fixed_cost：本次固定成本，已按同一成本口径归集，不自动判断进项税抵扣。
- buffer_rate：0–1，成本预留比例，非销售加成。
- margin_rate：0–0.99，目标经营测算毛利率，分母为未税收入。
- fee_rate：0–0.99，按未税收入收取的手续费比例；与margin_rate之和必须小于1。
- tax_rate：用户确认的本次销项税额测算率0–1；不是脚本给出的法定税率。
- payment_ratios：1–12个0–1比例，和精确等于1。
- extra_hours、extra_hourly_cost：本次增项工时和成本；确定没有时显式填0，不填不算。
- offered_net：可选，已有客户未税报价。缺省按目标毛利反算；需大于0。

数字允许十进制字符串；拒绝布尔、非有限数及过大值。报价最多两位小数，本版不适用于日元等不使用两位小数的结算口径。不支持成本为负的抵扣行。案例中固定成本及税率均为合成假设。

## 公式

C = (Σ工时×内部小时成本 + 固定成本) × (1+预留比例)
最低未税报价 = C / (1 - 手续费率 - 目标毛利率)，向上取到分。
利润 = 所选未税报价 × (1 - 手续费率) - C。
含税报价 = 所选未税报价 + 按用户税率算的税额。
增项成本 = 新增工时 × 内部小时成本 × (1+预留比例)，增项价按相同毛利口径反算。
不加价的利润 = 原利润 - 增项成本。

手续费基于未税收入，仅模拟线性收费；阶梯费率、最低费用、含税收费、跨境税费需要另行核对。预留不代表已发生费用。付款最后一期吸收分位舍入差。

## 内部版模板

1. 项目与输入来源：匿名客户代号、来源定位、确认时间。
2. 范围矩阵：包含/排除/验收/修改次数/依赖。
3. 成本、预留、目标毛利和报价推导；已有报价是否低于目标。
4. 增项：前后范围、工时/物料、建议加价、未加价利润变化。
5. 不确定性、待确认事项和所需人工决策。

## 客户版模板

标题：项目报价草案（未发送）
- 项目目标和明确交付物。
- 验收与修改范围；额外修改如何重新评估。
- 未税报价、税额、含税总价及币种。
- 付款里程碑与金额；里程碑以用户确认内容为准，不只给百分比。
- 客户需提供的素材、时间安排前提和有效期（未知标待确认）。
- 增项按双方另行确认，不写不可执行的“无条件额外收费”。

不得出现内部小时成本、底价、毛利率。生成后逐项比较内外版本价格一致性。

## 三个验收场景

A. 合成样例：总预留成本3000，40%毛利→未税5000、税额300、总价5300；不是4200。
B. 增加5小时：预留增项成本600，未税增项最低1000；不收费则原利润2000降到1400。
C. 用户只说“做一套品牌方案，预算5000”：先列待确认成本和范围，不宣称5000可盈利。

## 隐私

输入中使用匿名项目名，不复制客户联系方式。内部版留本地，发客户前只选客户版；脚本不会发网络请求，但WorkBuddy对话可能使用云端模型，不能声称整个对话离线。
