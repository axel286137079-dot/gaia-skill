# 中文深度研究

输入一个课题，产出**带出处、带可信度分级、可溯源**的中文深度研究报告。核心不是「快速给结论」，而是「结论可信、证据可查、分歧说清」。

## 何时使用

- 用户要「深度调研 / 行业研究 / 情报调研 / 写研报 / 竞品分析 / 尽调」
- 用户要一份「能引用、能溯源」的研究报告，而非泛泛而谈
- 用户强调要「中文信源」「国内数据」「官方口径」

## 一、信源分级（四级，决定结论权重）

| 级别 | 信源类型 | 示例 | 采信规则 |
|---|---|---|---|
| **一级**（最高） | 官方/政府、学术、一手数据 | gov.cn 部委/统计局/央行/法院、知网/万方/维普/高校/arXiv、巨潮资讯公告、上深交所、裁判文书网 | 可单独支撑结论 |
| **二级**（高） | 权威媒体、垂直权威平台 | 新华社/人民日报/央视/财新/第一财经/澎湃/界面/21世纪经济报道/中新网、天眼查/企查查/艾瑞/IDC | 可支撑结论，优先采信 |
| **三级**（中） | 行业自媒体、专家专栏、社区高赞 | 知乎、公众号(mp.weixin.qq.com)、雪球、虎嗅、36氪 | 只能作线索/佐证，**需交叉验证** |
| **四级**（低） | 匿名论坛、社交片段 | 贴吧、微博段子、短视频评论、匿名贴 | **只作线索，不作论据** |

**原则**：一级 > 二级 > 三级 > 四级；冲突时采信更高级别，但要把差异如实标注。

## 二、检索策略

1. **关键词变体**：同义词 + 中英文 + 缩写（如「生成式引擎优化 GEO / Generative Engine Optimization」）。
2. **时间窗口**：默认近 1~2 年；历史数据、政策沿革单独标注年份，避免拿旧数据当现状。
3. **多引擎 + 定向检索**：通用 WebSearch 覆盖全貌，再针对垂直平台定向检索（政策→政府官网，企业→天眼查/企查查，公告→巨潮资讯，法条→裁判文书/北大法宝，学术→知网/arXiv）。
4. **官方口径优先**：涉及监管、主权、政策的事实，一律以官方发布为准。

## 三、交叉验证规则（反幻觉核心）

- **关键事实/数据 ≥ 2 个独立信源**（不能是同一条消息的转载）。
- **单一信源（尤其三级）不得支撑核心结论**——最多写「据某来源，待核实」。
- **数字必须可溯源**：报告里每个具体数字都要能查到出处，查不到就删或标「待核实」。
- **冲突要标注**：不同信源口径不一致时，并列呈现 + 说明差异 + 给出采信理由。

## 四、报告结构（输出模板）

```markdown
# 《课题》深度研究报告

## 结论先行（TL;DR）
1. …（每条结论标注来源级别）

## 一、背景与问题定义
## 二、分章节论证（每段标注 [来源N·信源名·级别]）
## 三、数据与证据（表格 + 出处）
## 四、分歧与争议（不同观点并列）
## 五、未证实 / 待补充项
## 六、信源清单（按分级排列，附链接）
```

## 五、反幻觉红线（必须遵守）

- **不编造**数据、引文、URL、人名、日期；查不到就说查不到。
- **区分「事实」与「观点/推测」**：观点要标明是谁的观点。
- **不确定就标注**「未证实 / 待核实」，不要用肯定语气掩盖信息缺口。
- **引用可追溯**：每个 [来源] 都要有可点击链接或可检索定位。

## 六、质量自检（交稿前跑一遍）

交稿前用 `bin/source_audit.py` 做信源审计：

```bash
python3 bin/source_audit.py 报告.md
# 输出：信源分布统计（各级占比）+ 反幻觉警示（无出处陈述/单一信源/未分级域名）
```
