# GEO-CN：懂国产引擎的生成式引擎优化

让内容被「会回答问题的 AI」检索、引用、归因，而不是只被搜索引擎收录。

## 何时使用本 skill

出现以下任一意图，即启用本 skill：

| 用户意图 | 典型说法 | 走哪条流程 |
|---|---|---|
| 检查内容「够不够被 AI 引用」 | 帮我看看这篇文章 AI 会不会引用 / 能不能被 DeepSeek 提到 | 流程 A：可引用度审计 |
| 让内容更适合某个 AI 引擎 | 帮我改成豆包爱引用的风格 / 让 Kimi 收录我 | 流程 B：分诊式改写 |
| 想知道竞争对手在 AI 里表现如何 | 看看同行在 ChatGPT/豆包里怎么被回答的 | 流程 C：竞品 AI 引用对比 |
| 长期布局「AI 引用我」 | 怎么让 AI 优先推荐我的产品 | 流程 D：信源布局方案 |

**一句话原则**：生成式引擎不看 SEO 那套（关键词密度、外链、权重），它看的是「这段内容是否值得被当作可信答案引用」——可验证性 > 风格。

## 核心方法论：GEO 九法（Princeton GEO-bench 实测）

下表以 Princeton GEO 论文（arXiv:2311.09735）的实验为方法参考；论文结果不应直接外推为任一国产引擎的实际引用概率：

| 方法 | 效果 | 中文实操 |
|---|---|---|
| ① Quotation Addition 专家引言 | **+30~41%** | 开头放一句有出处的专家/权威引言 |
| ② Statistics Addition 数据 | **+31~40%** | 植入可验证的数字、百分比、年份 |
| ③ Cite Sources 引用来源 | **+27~42%** | 文末列「参考来源」：链接、报告名、机构 |
| ④ Fluency Optimization 流畅度 | +15~28% | 短句、衔接词、消除歧义 |
| ⑤ Authoritative 权威语气 | +10~18% | 肯定式结论 + 领域术语 |
| ⑥ Technical Terms 术语 | +8~18% | 用准确专业名词，别用大白话替代 |
| ⑦ Easy-to-Understand 简化 | +3~14% | 长难句拆短、给类比 |
| ⑧ Unique Words 独特词 | ≈0 | **无效，不用刻意做** |
| ⑨ Keyword Stuffing 关键词堆砌 | **-8~10%（有害）** | **严禁**，堆关键词反而被 AI 判为低质 |

**三条核心洞察**（务必内化）：
1. **可验证性 > 风格**：AI 引用你，是因为你能提供「它能转述的事实」，不是因为文笔好。
2. **组合 > 单一**：引用 + 数据 + 来源 三者叠加，效果好于任何单一方法。
3. **低权威站点收益最大**：小站/新站做 GEO 的边际提升（可达 +115%）远大于大站——这是普通人的机会。

### 2026 下半年信源规则重构（本轮最重要的变化，务必内化）

2026 年「3·15」之后主流平台完成新一轮信源规则重构，**「一套内容发全网」的打法基本失效**。核心是从「广撒网」转向「精筛选」：

| 平台 | 2026 H2 规则变化 | 落地动作 |
|---|---|---|
| **DeepSeek** | 最终**精读信源从 10~15 个压缩到 4~5 个**；新增**语义深度评分 / 信息增益值 / 信源等级权重**三项指标；「**孤证不采信**」需多独立信源交叉验证 | 内容必须有独家信息增量（原创数据/实测），同一事实至少 2~3 个独立信源互证 |
| **豆包** | 上线**可信度分层机制**：单一信源在同一答案中的引用占比被压到 **8% 以内**，并强制要求**≥3 个独立信源交叉验证**；字节生态权重最高 | 别指望单篇爆款被反复引用；多平台同口径铺开，且必须做多源互证 |
| **文心一言** | **E-E-A-T 权重提升到约 40%**；百度系内容引用率 **81.7%** | 补作者资质、机构背书、更新时间；百科/百家号打底 |
| **腾讯元宝** | 公众号、视频号里的**官方认证内容被抬到站外采集内容之上**；已接入 ima 知识库 | 优先做公众号认证主体原创，而非外部转载 |
| **通义千问** | 强化**可验证商业事实**（销量、排名、融资额） | 内容中植入可核验的经营数据 |
| **Kimi** | 仍偏长文档与信息密度（知乎、B 站长篇） | 白皮书/研报带数据附录 |

**三条新铁律**：

1. **端口差异不可忽略**：同一个模型换个端口，权重差一倍以上。例：豆包 **App 端**引用抖音内容占比接近 **30%**，**Web 端**直接掉到 **11.85%**；在目的地推荐、攻略类问题上豆包对抖音内容引用率高达 **97.7%**。判断「哪个平台有用」必须加上「哪个端口、哪个场景」两个限定条件。
2. **同质化通稿触发低质标记**：算法已能做语义级特征提取，识别文章之间的同质化关系。一篇通稿改十版发十个平台 = 一篇内容重复出现，**不加权重反而触发低质标记**；2026-08 后部分平台会主动标注「内容或为营销软文，建议谨慎甄别」。
3. **验证周期显著拉长**：内容从发布到被采纳，过去平均 **30 分钟**，现在部分场景延长到 **3~5 天**。别用「发完立刻查不到」判断策略失败。

**信源权威梯度**（据 Forrester 2026 Q2 报告，各平台判断高度一致）：

| 层级 | 信源类型 | 引用概率 |
|---|---|---|
| 天花板 | 央媒 / 国家级媒体 | 60%~70%（是普通自媒体的 **9.4 倍**） |
| 核心 | 省级重点新闻网站 / 地方官媒 | 区域传播与交叉验证主力 |
| 有效 | 行业垂媒、知乎、技术社区、认证公众号 | 需配合多源互证 |
| 低效 | 批量软文、模板站、无作者信息的聚合页 | 被降权或标注为营销内容 |

> **对个人的启示**：既然央媒权重天花板难以触及，个人/小团队的突破口是 **信息增益**——提供别人没有的一手数据（实测、调研、案例），用「原创数据 + 多源互证 + 清晰来源标注」去换引用，而不是拼发稿量。

### 分平台引用周期（2026 实测，用于排发布节奏）

**收录 ≠ 引用**：入库只是进了候选池。首次被引用快则 2~7 天，而要在两三个平台形成**稳定引用**通常需持续输出 **3~6 个月**。硬广和水文即使一度被收录，后续更新中也会被清掉（引用是动态换血）。各平台实测节奏差异明显：

| 平台 | 实测首次引用周期 | 主要抓取信源 | 内容偏好 |
|---|---|---|---|
| **豆包** | **4~7 天（四家中最快）** | 今日头条系（头条号）、抖音生态；字节内容加权明显 | FAQ 口语化问答、结论前置、列表对比 |
| **腾讯元宝** | 7~14 天 | 微信公众号（引用占比约 15%~20%+）、腾讯新闻；深度决策时转调外部权威媒体 | 权威解读型长文、客观数据、专业背书 |
| **通义千问** | 10~18 天 | 搜狐号、网易号、知乎、阿里云开发者社区等阿里系；企业官网 | 表格/列表式模块化内容、行业数据报告 |
| **DeepSeek** | **15~30 天（偏慢但覆盖最广）** | CSDN、知乎、博客园等技术社区；新华网等权威媒体；搜狐/网易等门户 | 数据型深度长文、参数表、技术细节 |

**排期含义**：
- 需要**短期见效**的场景（活动、上新）优先铺豆包友好的头条号/抖音口径内容；但别指望它长期独占引用（单源占比被压到 8%）。
- **B 端与技术选型**内容优先铺 DeepSeek 口径（技术社区 + 权威媒体 + 官网结构化事实），见效慢但引用覆盖率四家最广、生命周期最长。
- 内容发布后 **3~5 天查不到属正常**，不要据此判定策略失败；至少观察 2~4 周再看趋势。

## 工作流

### 流程 A：可引用度审计（用脚本）
对一段文本跑 9 法打分，输出「可引用度」评分 + 逐项缺失建议。

```bash
python3 bin/citability_audit.py <你的内容.md|.txt>
```

输出示例见「输出格式」。脚本纯标准库，无需任何 key，离线可跑。

### 流程 B：分诊式改写（用脚本）
按目标引擎生成改写版本：

```bash
python3 bin/multi_engine_rewrite.py <内容> --engine doubao|deepseek|kimi|tongyi|wenxin|hunyuan|zhipu|xunfei|minimax|xiaomi|pangu|step|baichuan|yi|sensenova|skywork|metaso|nano360
```

脚本会：① 应用该引擎的优化规则重排内容；② 输出该引擎专属的改写版本骨架；③ 给出「还需补什么」的清单。若配置了 LLM API key，则直接生成改写全文（见脚本内 `--api-key` / 环境变量 `GEO_API_KEY`）。

### 流程 C：竞品 AI 引用对比（人工 + WebSearch）
没有国产引擎的官方开放 API，此流程用 WebSearch 模拟：
1. 用 WebSearch 检索「竞品品牌 + 关键词」，观察各引擎结果页里竞品是否被引用、以什么姿态被引用。
2. 记录竞品在「专家引言 / 数据 / 来源」三个维度上做了什么，你缺什么。
3. 输出对比表。

### 流程 D：信源布局方案（人工产出）
为长期被 AI 引用，产出一页纸布局方案：在哪些信源（公众号/百科/官网/社区/PDF）放什么内容，形成「AI 可引用的证据链」。

2026 H2 规则下，布局方案必须包含这四项，否则不算合格：
1. **多源互证清单**：同一核心事实的 ≥3 个独立信源落点（应对豆包 8% 单源占比上限与 DeepSeek「孤证不采信」）。
2. **信息增益说明**：你能提供而全网没有的一手数据是什么（实测、调研、案例、原始统计）。
3. **端口与场景限定**：目标用户是在 App 端还是 Web 端提问、属于哪类场景（如目的地推荐 vs 消费决策），据此决定渠道优先级。
4. **差异化而非复制**：各渠道内容必须是真正改写/延展，不是同稿分发（同质化会触发低质标记）。
5. **发布节奏与预期管理**：按上表「分平台引用周期」排期（豆包 4~7 天 / 元宝 7~14 天 / 通义 10~18 天 / DeepSeek 15~30 天），并把「稳定引用需 3~6 个月持续输出」写进预期，避免用短期数据否定策略。

## 输出格式

审计报告统一用以下结构：

```
## 可引用度审计报告
- 总分：XX / 100
- 等级：高可引用 / 中等 / 低可引用
- 已达标：①②③…
- 缺失项：④⑤…（附具体补法）
- 一句话结论：……
```

改写输出统一结构：

```
## [引擎名] 改写版
- 改了哪些点（规则 → 动作）
- 改写正文（或骨架）
- 还需补齐：引用来源 / 数据 / 专家引言…
```

## 合规与边界

- 严禁造假引用、编造数据、虚构专家引言——AI 会追溯来源，造假会反噬并可能引发平台处罚。
- 关键词堆砌（⑨）明确有害，任何情况下不推荐。
- 不做「保证被 AI 引用」的承诺；脚本分数仅用于内容复核和相对比较，不是平台收录或引用概率。
